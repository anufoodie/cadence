# references/

Supporting material — glossary, idea registers, templates, third-party reference material. Cited by `canonical/` and `features/` but not authoritative on its own.

**Status:** Empty. Populate as supporting material accumulates.

---

## What goes here

| File / folder | Purpose |
|---|---|
| `glossary.md` | Term definitions — personas, entity types, state vocabulary, abbreviations (when needed beyond what `memory/quick-reference.md` carries) |
| `ideas/` | Idea registers — promoted, candidate-promotion, parked-and-deprecated (use sub-files to keep them navigable) |
| `templates/` | Reusable templates — meeting notes, brief templates, pilot seed-data schemas |
| _project-specific_ | Whatever supporting material your project accumulates that doesn't belong in canonical or features |

## Cross-reference contract

References content is **informational**. Canonical / features can cite references for context but must not depend on references for binding decisions. If something in references becomes binding, lift it into canonical with a decision-log entry documenting the promotion.

## Distinction from canonical and archive

- **canonical/** — current binding spec content.
- **features/** — vertical deep-dives that depend on canonical.
- **archive/** — historical artifacts (read-only, superseded).
- **references/** — supporting material that informs but doesn't bind.
